# Анализ и моделирование данных предметной области

## 1. Описание предметной области

**Предметная область:** интернет-магазин.

Интернет-магазин занимается электронной торговлей товарами через интернет.

Основные процессы:
- ведение каталога товаров;
- работа с категориями товаров;
- формирование корзины покупателя;
- оформление заказов;
- обработка заказов;
- хранение информации о товарах;
- хранение информации о заказах клиентов.

Пользователи системы:
- покупатели интернет-магазина;
- сотрудники интернет-магазина.

Основные задачи информационной системы:
- хранение информации о товарах;
- хранение информации о категориях товаров;
- учет товаров в каталоге;
- формирование и хранение корзин покупателей;
- учет оформленных заказов;
- обработка заказов покупателей;
- просмотр информации о заказах.

## 2. Объекты данных


В предметной области выделены следующие основные объекты данных.

###Покупатель

Покупатель интернет-магазина, который просматривает каталог товаров и оформляет заказы.

Необходимо хранить:
- идентификатор покупателя;
- имя;
- номер телефона.

###Товар

Товар, представленный в каталоге интернет-магазина.

Необходимо хранить:
- идентификатор товара;
- идентификатор категории;
- название;
- описание;
- стоимость.

###Категория

Категория, к которой относятся товары интернет-магазина.

Необходимо хранить:
- идентификатор категории;
- название;
- описание.

###Корзина

Корзина покупателя, в которой хранятся выбранные товары перед оформлением заказа.

Необходимо хранить:
- идентификатор корзины;
- идентификатор покупателя.

###Заказ

Информация о заказе, оформленном покупателем в интернет-магазине.

Необходимо хранить:
- идентификатор заказа;
- идентификатор покупателя;
- дата оформления;
- общая стоимость;
- статус заказа.

###Товар в заказе

Информация о товаре, включённом в определённый заказ.

Необходимо хранить:
- идентификатор товара в заказе;
- идентификатор заказа;
- идентификатор товара;
- количество;
- стоимость товара на момент оформления заказа.

## 4. Классификация данных

Выделенные данные можно классифицировать по их назначению и типу.

| Категория данных | Примеры | Назначение |
|---|---|---|
| Текстовые | имя покупателя, телефон, название товара, описание товара, название категории, статус заказа | Хранение текстовой информации об объектах |
| Числовые | идентификаторы, стоимость товара, количество | Хранение числовых значений |
| Даты и время | дата оформления заказа | Хранение информации о датах событий |
| Логические | отсутствуют в текущей модели | В текущей модели данные типа «да/нет» не используются |
| Справочные | категории товаров, каталог товаров | Хранение перечня доступных товаров и категорий |
| Вычисляемые | общая стоимость заказа | Значение может быть рассчитано на основе стоимости и количества товаров в заказе |

## 5. Связи между объектами

### Покупатель - Корзина

Тип связи: один ко многим (1:N).

Один покупатель может иметь несколько корзин. Каждая корзина принадлежит одному покупателю.

### Категория - Товар

Тип связи: один ко многим (1:N).

Одна категория может содержать несколько товаров. Каждый товар относится к одной категории.

### Покупатель - Заказ

Тип связи: один ко многим (1:N).

Один покупатель может оформить несколько заказов. Каждый заказ относится к одному покупателю.

### Заказ - Товар в заказе

Тип связи: один ко многим (1:N).

Один заказ может содержать несколько товаров. Каждая запись о товаре относится к одному заказу.

### Товар - Товар в заказе

Тип связи: один ко многим (1:N).

Один товар может входить в несколько заказов. Каждая запись о товаре в заказе относится к одному конкретному товару.

## 6. Концептуальная модель данных

На схеме отражены следующие связи:

- Покупатель 1:N Корзина;
- Категория 1:N Товар;
- Покупатель 1:N Заказ;
- Заказ 1:N Товар в заказе;
- Товар 1:N Товар в заказе.

Связь многие ко многим между заказом и товаром реализована с помощью промежуточной таблицы «Товар в заказе».

## 7. Оценка качества исходных данных

После построения концептуальной модели была выполнена оценка полноты и качества данных.

### Достаточно ли объектов выделено?

Да. Выделенные объекты описывают основные данные, необходимые для учета покупателей, товаров, категорий, корзин и заказов.

### Отсутствуют ли важные сущности?

Для рассматриваемой модели основных сущностей достаточно. При дальнейшем развитии системы могут быть добавлены платежи, доставка, отзывы покупателей и другие объекты.

### Все ли необходимые атрибуты определены?

Для построения концептуальной модели определены основные атрибуты каждого объекта. При реализации реальной информационной системы набор атрибутов может быть расширен.

### Имеются ли дублирующиеся данные?

Явного дублирования данных в модели нет. Информация о покупателях, товарах, категориях, корзинах и заказах хранится в отдельных объектах и связывается между собой.

### Достаточно ли информации для дальнейшего проектирования информационной системы?

Да. Выделены основные объекты, их атрибуты и связи. Полученная модель может использоваться как основа для дальнейшего проектирования базы данных.

## Вывод

В ходе лабораторной работы была проанализирована предметная область интернет-магазина. Были выделены основные объекты данных, определены их атрибуты и выполнена классификация данных.

Между объектами были определены связи один ко многим и многие ко многим. Связь между заказом и товаром реализована с помощью промежуточного объекта «Товар в заказе». На основе проведенного анализа была построена концептуальная модель данных.

Полученная модель описывает основные данные интернет-магазина и может использоваться как основа для дальнейшего проектирования информационной системы.
